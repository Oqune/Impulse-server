# Relay resource and lifecycle hardening

Date: 2026-10-14
Scope: server-only reliability hardening and auth-parameter consistency; no cryptographic primitive, certificate selection, Wire v3 field layout, or client source changed.

## Changes

- Packet-handler errors now exit the session reader loop, after which the existing `JoinSet` teardown aborts the writer, reconciles reader buffers, and removes session/auth/key-exchange state (`src/relay/session.rs:419`). A live loopback regression sends a valid but unauthenticated Data frame and observes stream closure (`src/ui/live_tests.rs:58`).
- Session admission now times out waiting for the client-initiated bidirectional stream and applies a non-renewable 30-second deadline from challenge issuance through challenge delivery, reads, and packet processing (`src/relay/session.rs:171`, `src/relay/session.rs:199`, `src/relay/session.rs:486`). The auth deadline is checked only while transitioning to authenticated; authenticated traffic continues under the 300-second idle timeout. Heartbeat already required authentication; loopback verifies pre-auth Heartbeat closes and authenticated Heartbeat continues beyond 30 seconds (`src/ui/live_tests.rs:92`).
- A single `Notify` is translated to a cloneable watch cancellation signal so both dual-stack accept loops stop from one notification (`src/relay/mod.rs:126`, `src/relay/mod.rs:325`). A unit regression waits for both receivers to observe the signal.
- `MessageStore` now retains at most 10,000 messages and 64 MiB of payload bytes, evicting oldest entries first and updating byte accounting during TTL sweeps (`src/storage/mod.rs:24`, `src/storage/mod.rs:96`).
- Sync captures a high-water ID, advances a bounded cursor through that snapshot, emits frames no larger than 4 MiB and fewer than 500 messages, and sends empty SyncResponse for an empty result (`src/relay/auth.rs:217`, `src/protocol/limits.rs:20`). This stays below the Android stream accumulator's 8 MiB cap and below its 500-message auto-follow-up threshold, preserving the existing wire layout and cursor meaning.
- Sync is admitted by a 16-operation semaphore. A second 16-slot budget is acquired before cloning a page; its owned permit travels with the encoded response and is released only after writer flush, send failure, or task drop (`src/relay/mod.rs:55`, `src/relay/mod.rs:60`, `src/relay/session.rs:200`). The application-level working set is bounded to roughly 128 MiB for concurrent page/encoded-frame pairs plus container overhead. This does not bound WebTransport/QUIC internals or total process memory.
- Both the full Sync operation (admission, page construction, and response-channel backpressure) and each Sync writer flush are capped at 30 seconds; expiration ends the session so queued frame permits are dropped rather than pinned by a non-reading peer (`src/relay/session.rs:32`, `src/relay/session.rs:360`, `src/relay/session.rs:475`). A very large/slow sync may need to resume from the last processed ID after reconnect.
- Key-exchange replay retains at most 16 packets and 64 KiB per session, evicts oldest packets, skips retaining a packet that cannot fit, and removes the session cache on disconnect (`src/relay/mod.rs:95`, `src/relay/session.rs:521`). Live opaque relay remains unchanged.
- The test named `many_client_auth_and_opaque_payload_storage` now clearly states that it tests helper/storage behavior only; it does not claim to validate server-side recipient isolation or live routing (`tests/multi_client_stress.rs:45`).
- Configured auth hashes are now parsed and bounded once at startup as Argon2id v19 with a 32-byte output, at least 16 salt bytes, and supported `m=47104..65536`, `t=3..6`, `p=1..2` (`src/crypto/mod.rs:22`, `src/config/mod.rs:79`, `src/relay/mod.rs:212`). Runtime challenges advertise the exact validated tuple in the existing parameter tag; the compatibility encoder still emits the canonical default and the Wire v3 layout is unchanged (`src/protocol.rs:312`, `src/protocol.rs:320`, `src/relay/session.rs:197`). Validation failures do not echo configured hash contents.

## Verification

- Final `cargo test --locked` passed after the review correction: library 78/78; integration suites attack_simulations 4/4, config 13/13, exploits 8 passed with 2 existing client-side-only tests ignored, handshake 16/16, multi_client_stress 3/3, relay 10/10, and storage 9/9 (141 passed, 2 ignored total).
- The focused non-default auth integration test proves a supported custom tuple is advertised exactly and the client-derived HMAC verifies against the server's stored output (`tests/handshake.rs:35`). Config tests verify valid custom settings pass and unsupported algorithm errors do not echo the hash (`src/config/mod.rs:219`).
- The final full run also exercises absolute auth-deadline calculation, Sync admission and writer timeouts, permit release on failure/drop/abort, and the production WebTransport loopback with pre-auth Data/Heartbeat closure, authenticated heartbeat traffic beyond 30 seconds, and a 5 MiB Sync backlog split into frames no larger than 4 MiB (`src/relay/session.rs:635`, `src/ui/live_tests.rs:92`). The focused live test passed 1/1 in 37.27 seconds.
- `cargo build --locked` and `cargo clippy --locked --all-targets -- -D warnings` passed on the same final source state. Windows emitted non-failing linker stdout notices while creating import libraries.
- An initial full test run exposed a fixed nonce collision in the new integration-test fixture's process-global replay helper; the fixture now uses a random nonce, and the complete test suite was rerun successfully.
- Final review caught that a redundant auth-deadline check could close an already-authenticated session after 30 seconds. The check now applies only to the unauthenticated-to-authenticated transition. A production QUIC loopback regression keeps sending and verifies heartbeat responses beyond the auth deadline; the full test/build/clippy gate was rerun successfully after the correction.

## Boundaries

No live dual-stack socket shutdown test was run; shutdown fan-out is covered at the watch-receiver level. The existing tests named `multi_client_*` are storage/auth helper simulations rather than multi-client live routing tests; the separate `ui::live_tests` case exercises the production WebTransport relay path with two authenticated clients. Certificate rotation, TUI behavior, the HMAC/Argon2 primitives, and Wire v3 field layout were not changed by this work; startup hash validation and challenge parameter advertisement were hardened.
