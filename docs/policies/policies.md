# Policies — Свод правил и стандартов проекта Impulse

Этот файл является обязательным инженерным контрактом при разработке клиента и сервера.

## 1. Прозрачность разработки и участие ИИ
- Разработка ведется в рамках парадигмы AI-Assisted Engineering (см. `AI_MANIFESTO.md`).
- Запрещен неконтролируемый код: каждая строчка должна иметь четкое инженерное обоснование.
- Все решения фиксируются в спецификациях и документации.

## 2. Коммиты и контроль версий
- **Формат:** Conventional Commits (`feat:`, `fix:`, `docs:`, `refactor:`, `style:`, `test:`, `chore(release):`).
- **Атомарность:** Один логический блок изменений = один коммит.
- **Язык сообщений:** Английский язык, без эмодзи, с кратким и емким описанием сущности изменений.
- **Исключения:** Никогда не коммитить секреты, билды (`build/`, `target/`, `*.apk`), дампы памяти, логи и временные артефакты агентов.

## 3. Стратегия ветвления (Trunk-based)
- Ветка `master` всегда стабильна и готова к релизу.
- Фичи и фиксы разрабатываются в коротких тематических ветках (`feat/<topic>`, `fix/<topic>`) и вливаются в `master` после прохождения test-gate.
- Никаких долгоживущих заброшенных веток.

## 4. Критерии приемки (Test-gate)
- Перед коммитом код обязан проходить локальную проверку:
  - **Client:** `./gradlew testDebugUnitTest` (требуется JDK 17+)
  - **Server:** `cargo test` и `cargo clippy -- -D warnings`
- Если тесты не проходят — коммит запрещен до полного устранения ошибок.

## 5. Криптографические и протокольные инварианты
- Изменения криптографических примитивов (ML-KEM, ML-DSA, AES-GCM, Argon2id) — **только через SPEC и аудит**.
- Запрещено менять wire-протокол (опкоды `0x11`–`0x34`) без синхронных правок обоих репозиториев.
- Сервер не имеет доступа к ключам и открытому тексту (E2EE Zero-Knowledge Relay).

## 6. Безопасность логов
- Запрещено выводить в логи: пароли, сырые токены, приватные ключи, дампы полезной нагрузки пакетов.
- В логах фиксируются только длины пакетов, опкоды, сессионные идентификаторы и временные метки.

## 7. Стандарт версионирования (Protocol-Locked SemVer)
В проекте Impulse утверждён **двухуровневый SemVer с фиксацией протокола**:
`v<ProtocolMajor>.<ComponentMinor>.<Patch>`

### Историческая эволюция архитектуры
- **v0.x.y (Legacy Prototype):** Plaintext WebSocket (`ws://`). Начальный концептуальный прототип локального мессенджера.
- **v1.x.y (Legacy Secured):** WebSocket Secure (`wss://`). Канал защищён стандартным TLS-сертификатом.
- **v2.x.y (Transitional WebTransport):** Архитектурный переход на WebTransport (QUIC / UDP 4433) и начало внедрения постквантового шифрования. В силу активных исследовательских изменений архитектуры строгая совместимость между минорными релизами `v2.x` соблюдалась не всегда (клиент дошёл до v2.9.x, сервер — до v2.7.x).
- **v3.0.0+ (Current Production Era):** Введение строгого Protocol-Locked SemVer. Wire-протокол стабилизирован и зафиксирован (опкоды `0x11`–`0x34`).

### Правила версионирования v3+
1. **ProtocolMajor (первая цифра, текущая 3):**
   - Строго привязана к мажорной версии бинарного Wire-протокола (опкоды `0x11`–`0x34`, схема E2EE, ML-KEM-768/ML-DSA-65).
   - Любое несовместимое изменение wire-формата инкрементирует `ProtocolMajor` синхронно для клиента и сервера (например, переход в `v4.0.0`).
   - **Инвариант совместимости:** Любой клиент `v3.X.Y` гарантированно совместим по сети с любым сервером `v3.A.B`.
2. **ComponentMinor (вторая цифра):**
   - Отражает независимый цикл разработки компонента (Android-клиента или Rust-сервера).
   - Инкрементируется при добавлении обратной совместимой функциональности (новые экраны, разделы TUI, настройки).
   - Текущие релизные линейки: Client `v3.0.x`, Server `v3.0.x`.
3. **Patch (третья цифра):**
   - Инкрементируется при исправлениях ошибок, усилении безопасности, оптимизации производительности и UI-полировке без изменения публичного API и протокола.
4. **Стандарт именования тегов и релизов:**
   - Git-теги: строго `v<Major>.<Minor>.<Patch>` (строчная `v`, три числа через точку, без суффиксов, например `v3.0.0`).
   - Заголовки релизов на GitHub:
     - Client: `Impulse Client v<Major>.<Minor>.<Patch>`
     - Server: `Impulse Server v<Major>.<Minor>.<Patch>`
   - Описания релизов (Patch notes):
     - Строго без эмодзи.
     - Обязательная таблица совместимости архитектур с прямыми ссылками на артефакты.
     - Структурированный технический список изменений с указанием CVE / модели угроз.
     - Двуязычный формат (English + Russian).
